# TravelHub

Настольное приложение для туристов, гидов и местных производителей. Это не сайт: окно программы на GTK 4 и libadwaita, данные в MariaDB.

Турист смотрит экскурсии и лавку своего региона, бронирует место и оставляет заявку гиду. Гид ведёт маршруты и очередь заявок. Производитель продаёт товары. Администратор видит сводку и может назначить гида вручную или автоматически.

## Запуск

Нужны Python 3, GTK 4 и libadwaita. На Omarchy они уже стоят, отдельные пакеты ставить не нужно.

Из корня проекта:

```bash
python3 -m venv --system-site-packages .venv
source .venv/bin/activate
pip install -r requirements.txt
python main.py
```

То же самое: `python -m travelhub`.

Готовая программа без исходников собирается так:

```bash
python -m venv --system-site-packages .venv
.venv/bin/pip install pyinstaller
.venv/bin/pyinstaller --noconfirm travelhub.spec
```

Файл запуска: `dist/travelhub/travelhub`. Это программа для Linux. Файл `.exe` для Windows эта сборка не делает: окно завязано на GTK этой системы.

При первом запуске в MariaDB создаются таблицы и демо-данные (если база пустая). Повторный запуск эти строки не дублирует.

Подключение: `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`, `DB_NAME` (по умолчанию база `travelhub`).

При таймауте к `178.248.7.5` запустите `../mariadb-tunnel.sh` из репозитория `Practica Devok4ki`, затем `export DB_HOST=127.0.0.1 DB_PORT=3406`.

## Вход

| Кто | Логин | Пароль |
| --- | --- | --- |
| Администратор | `admin` | `admin` |
| Гиды | `sokolov`, `belova`, `kuznetsov`, `morozova`, `volkova`, `lebedev` | `guide` |

Регистрация в окне входа создаёт только туриста. Роль гида или производителя назначает администратор.

Направления гидов: Соколов — природа, Карелия; Белова — история, Золотое кольцо; Кузнецов — гастрономия, Калининград; Морозова — город, Байкал; Волкова — активный отдых, Алтай; Лебедев — универсальный, любой регион.

Производители: Павлова — мёд и варенье, Алтай; Романова — береста и лён, Карелия; Орлов — рыба и марципан, Калининград.

## Роли

**Турист** видит открытые экскурсии и бронирует место, пока есть свободные. Создаёт заявку гиду и видит только свои. В лавке заказывает товары местных производителей. После завершённой поездки, заявки или заказа может поставить оценку.

**Гид** публикует экскурсии, видит свои брони и очередь. Свободную заявку можно взять. По своим заявкам завершает работу или отменяет. Отмена экскурсии снимает действующие брони.

**Производитель** ведёт свои товары и остатки. Новый заказ принимает, отмечает готовность и выдачу. Отмена возвращает товар на склад. Турист может отменить только ещё не принятый заказ.

**Администратор** видит сводку, всех людей, заявки, экскурсии, брони, заказы и товары. Меняет роль, направление, регион и активность. Назначает гида вручную или запускает подбор. Отключение гида возвращает его открытые заявки в очередь. Последнего активного администратора снять нельзя.

## Как назначается гид

У каждого активного гида считается балл:

- совпало направление с заявкой: +40;
- универсальный гид: +12;
- тот же регион: +18;
- гид с регионом «любой»: +8;
- средняя оценка туристов умножается на 4; если оценок ещё нет, берётся нейтральные 4,2;
- за каждую заявку в работе снимаются баллы: 3 за низкий приоритет, 5 за обычный, 9 за высокий;
- гид с четырьмя и более активными заявками не выбирается, пока есть кто-то ниже этого предела. Если на пределе все, берётся наименее загруженный.

Срочные заявки распределяются раньше. В карточке после автоматического назначения видно, почему выбран именно этот гид.

На странице экскурсии турист также видит товары производителей того же региона.

```

  __init__.py

  db.py                 MariaDB: люди, заявки, экскурсии, брони, лавка, журнал
```

## База

Сервер MariaDB, схема в базе `travelhub` (или значение `DB_NAME`).

- `users` — одна таблица учётных записей. Роль хранится в поле `role`: `admin`, `guide`, `producer`, `tourist`. Логин уникален.
- `requests` — заявки туристов гидам. Открытая заявка с той же темой у того же туриста второй раз не создаётся.
- `tours` и `bookings` — экскурсии и брони. Мест не может стать меньше нуля: когда места кончаются, экскурсия помечается «мест нет».
- `products`, `orders`, `order_items` — лавка. Цена в заказе фиксируется на момент покупки, остаток уменьшается сразу.
- `reviews` — одна оценка туриста на гида, экскурсию или товар. Рейтинг гида — среднее этих оценок.
- `messages` — переписка по заявке.
- `history` — журнал: создание, назначение, смена статуса.

Пароли хранятся как хеш, не открытым текстом.
